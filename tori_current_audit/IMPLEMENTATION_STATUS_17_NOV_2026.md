# Tori-Wear implementation continuation — 17 November 2026

## Source-code work completed in this pass

### Persistent authentication lifecycle
- Production password-reset requests now look up accounts in MySQL rather than relying on process-local demo users.
- Reset tokens are SHA-256 hashed, single-use, expire after 15 minutes, and are consumed in a database transaction with the password update and active-session revocation.
- Production reset email delivery uses Resend credentials from the enabled API vault or server environment. Responses remain generic to avoid account enumeration.
- Staff invitations now have a persistent `staff_invitation_tokens` table, hashed single-use tokens, 48-hour expiry, and database-transaction activation.
- Added an Admin activation route and password-creation screen.
- Added in-process request throttling for password reset and activation endpoints.

### Central API & integrations vault
- Vault records now support encrypted JSON credential sets rather than only one secret string. Existing single-secret records remain readable.
- Added edit/replace, enable/disable, delete and fixed-endpoint connection tests for Resend, Meta WhatsApp, Razorpay, Shiprocket, OpenAI and Google AI.
- Secrets are never returned to the browser. A strong 32-byte `API_CREDENTIALS_ENCRYPTION_KEY` is required.
- Resend and Meta WhatsApp send services and webhook verification now resolve enabled vault credentials (server environment variables take precedence).
- Razorpay payment operations and the public checkout key endpoint can use enabled vault credentials.
- Shiprocket adapter initialization and webhook token validation can use enabled vault credentials.
- Gemini text/image generation can use enabled Google AI vault credentials.
- Gmail OAuth refresh-token delivery now supports Early Access and password-reset/staff-invitation email. Unknown/custom providers are stored but cannot execute arbitrary URLs; a reviewed provider connector remains necessary. OpenAI supports connection test only; Gmail OAuth refresh-token delivery is implemented, but account consent and token issuance remain external setup.

### Dynamic Early Access coupons
- Campaign drafts now persist an optional coupon code.
- The composer lists active coupons from the main coupon manager.
- Draft creation and campaign dispatch revalidate the selected coupon against the main coupon repository.
- Email and WhatsApp campaign templates receive the selected campaign coupon instead of hard-coded TORI100.
- New Early Access registrations no longer automatically receive TORI100.

### Reverse logistics
- Implemented a Shiprocket return-shipment adapter using the reverse-shipment endpoint, followed by AWB assignment and pickup scheduling when required.
- Added persistent RETURN shipment type records without overwriting the forward AWB.
- Added Admin order drawer action to request full-order return pickup for delivered orders.
- Return webhooks now update the return shipment and mark the order RETURNED only when the reverse parcel is delivered; inventory restock is triggered at that point.
- Live Shiprocket account testing is still required; a return shipment created without an AWB is persisted as pending and must be reconciled before retrying.

### Persistent media storage
- Implemented a real Google Cloud Storage adapter using `@google-cloud/storage`.
- CMS base64 and chunked uploads now use the configured storage adapter; chunk staging is outside the public directory.
- Local storage remains available for development and its paths are constrained against traversal.
- GCS media is public-read by default to preserve the existing public-URL upload contract. The bucket must allow object-level public access.
